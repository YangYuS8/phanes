# Phanes v1 路线图

本文定义 Phanes 第一个稳定大版本的规划路径。它是规划契约，不保证所有细节不变；契约变更仍需显式 review。

## 目标

发布一个以 Windows 为主、本地优先、离线的 runtime、资源缓存构建器与 launcher 框架。它应安全、可复现、契约驱动，并明确不是公网服务器框架。

## 版本主题

| 版本 | 主题 |
| --- | --- |
| v0.1 | 契约基线与 embedded-minimal 端到端 |
| v0.2 | Runtime 生命周期、配置与诊断 |
| v0.3 | 资源缓存契约强化 |
| v0.4 | 存档数据基础 |
| v0.5 | 本地 profile/account 模型 |
| v0.6 | 面向 launcher 的 runtime API |
| v0.7 | Windows launcher 原型 |
| v0.8 | 本地 source 检测与导入准备 |
| v0.9 | Release candidate 硬化 |
| v1.0 | 稳定的 Windows 优先本地版本 |

## v0.1：契约基线与开发者预览

### 范围

建立项目第一版稳定内部形状：

- generated protobuf contracts
- CLI command contracts
- runtime status/shutdown API contract
- resource cache manifest contract
- SQLite schema/migration contract
- embedded-minimal cache 端到端路径

### 退出标准

- fresh checkout 可以测试、构建 CLI、构建 embedded-minimal cache、验证 cache、在 `127.0.0.1` 启动 runtime、查询 status 并关闭。
- Runtime 永不绑定 `0.0.0.0`。
- Runtime 不下载资源。
- 不要求 GC-Resources。
- 除极小安全 fixture 外，不捆绑版权资源。

### 非目标

- 真实 launcher UI
- 真实游戏集成
- 公网托管
- 远程资源获取
- client patching 或 bypass 工作

## v0.2：Runtime 生命周期、配置与诊断

### 范围

让 runtime 成为可预测、可观测的 localhost-only 进程。

### 交付物

- versioned config schema
- `phanes config init`
- `phanes config validate`
- `phanes runtime start --config <path>`
- `phanes runtime status --json`
- `phanes runtime logs`
- runtime lockfile/PID handling
- clean shutdown timeout behavior
- `phanes diagnostics collect`

### 退出标准

- 无效配置给出可操作错误。
- 默认 host 总是 `127.0.0.1`。
- 显式 `0.0.0.0` 被拒绝。
- 缺失/无效 cache 时 runtime 拒绝启动。
- Runtime 能检测已运行实例。
- Windows 上日志和诊断易于定位。

## v0.3：资源缓存契约强化

### 范围

把 builder/cache 模型变成持久、仅本地、可复现的契约。

### 交付物

- versioned resource cache manifest
- 带清晰错误类别的 cache verifier
- builder output directory layout
- provenance metadata：source kind、tool version、schema version、content hashes
- `phanes cache info`
- `phanes cache clean`
- `phanes cache verify --strict`

### 退出标准

- Verifier 能发现缺失 manifest、schema mismatch、文件损坏/缺失、hash 无效和不支持的 cache version。
- embedded-minimal 输出保持 deterministic。
- Runtime 只通过文档化 cache contract 消费 cache。

## v0.4：存档数据基础

### 范围

引入与 resource cache 分离的 save-data 子系统。

### 交付物

- SQLite save database contract
- migration runner
- `phanes save init`
- `phanes save migrate`
- `phanes save backup`
- `phanes save export`
- `phanes save import`
- 明确 config、save data、generated cache 和 logs 的路径

### 退出标准

- Save DB 可独立于 cache 初始化。
- Cache 删除不能影响 saves。
- backup/export 格式有文档。
- migration 从空 DB 开始有测试。

## v0.5：本地 profile/account 模型

### 范围

定义安全的本地离线身份模型。它不是官方认证。

### 交付物

- local profile schema/contract
- `phanes profile create`
- `phanes profile list`
- `phanes profile select`
- `phanes profile delete --with-confirmation`
- runtime profile status endpoint
- local-only session model

### 退出标准

- Runtime 可使用选定本地 profile 启动。
- Profile 数据位于 save storage。
- Profile 删除不会意外删除 resource cache。
- 文档明确说明没有官方认证绕过，也不进行在线服务交互。

## v0.6：面向 launcher 的 runtime API

### 范围

只扩展足以支持 launcher 进程控制和诊断的 runtime API。

### 交付物

- finalized status/readiness/shutdown endpoints
- diagnostics API
- redacted config inspection endpoint
- cache/save/profile summary endpoints
- API compatibility policy

### 退出标准

- Launcher 仅使用文档化 API 控制 runtime。
- API 响应是 generated protobuf JSON 或通过 fixture 验证。
- shutdown 幂等。
- Runtime 保持 localhost-only。

## v0.7：Windows launcher 原型

### 范围

引入 Windows 优先 launcher shell，用于控制现有 CLI/runtime 行为。

### 交付物

- Tauri 2 launcher prototype
- runtime start/stop/status controls
- cache status display
- save/profile display
- log viewer
- diagnostics export button
- Windows packaging prototype

### 退出标准

- Launcher 能验证 cache、启动 runtime、展示 status、停止 runtime、打开 logs/diagnostics。
- Launcher 不静默修改系统设置。
- Launcher 不 patch clients。
- Launcher 不下载 runtime resources。

## v0.8：本地 source 检测与导入准备

### 范围

为用户提供的本地输入做准备，不捆绑版权内容。

### 交付物

- local source detection contract
- `phanes source detect`
- `phanes source inspect`
- `phanes cache build --source local-path --input <path>`
- cache manifest 中的 import provenance
- legal/resource boundary 文档

### 退出标准

- Builder 能消费 approved local input shapes。
- 未知或不完整输入安全失败。
- Runtime 只依赖 generated cache，不依赖 source path。
- 没有 remote download fallback。

## v0.9：Release candidate 硬化

### 范围

冻结 v1.0 契约，除非出现关键问题。

### 交付物

- runtime API、cache manifest、save schema、config schema 和 CLI 行为的 freeze candidates
- Windows release candidate artifacts
- 完整文档站：quick start、config、builder/cache、runtime、launcher、diagnostics、boundaries
- migration/upgrade guide
- release checklist
- known issues document

### 退出标准

- fresh Windows 路径已测试。
- 现有 cache/save upgrade 路径已测试。
- Launcher 无需开发工具即可运行。
- release artifact 有 checksum。
- 不存在未文档化跨模块 JSON contract。

## v1.0：第一个稳定本地优先版本

### 必需能力

Runtime：

- 默认绑定 `127.0.0.1`
- 有文档化 status/readiness/shutdown API
- 使用本地 config、本地 save data 和本地 resource cache
- 不下载资源
- 提供有用诊断

Builder/cache：

- 支持 embedded-minimal cache generation
- 如 v0.8 已就绪，支持 approved local input cache generation
- 生成 versioned cache manifests
- 验证 cache integrity
- cache 与 save data 分离

Storage：

- SQLite migrations versioned and tested
- save data 支持 backup/export/import
- cache deletion 不能破坏 save data

CLI：

- config、cache、save、profile、runtime、diagnostics、version 命令稳定

Launcher：

- Windows-focused
- 可 start/stop runtime
- 展示 runtime/cache/profile status
- 打开 logs/diagnostics
- 不 patch clients，不静默修改系统网络设置

Releases：

- GitHub Releases 产出 Windows artifacts
- 发布 checksums
- docs 发布到 GitHub Pages
- 包含 upgrade notes

### v1.0 release gate

```bash
go test ./...
go vet ./...
phanes version
phanes config init
phanes config validate
phanes cache build --source embedded-minimal
phanes cache verify --strict
phanes save init
phanes profile create local-test
phanes runtime start
phanes runtime status
phanes diagnostics collect
phanes runtime shutdown
```

### v1.0 非目标

- 公网服务器托管
- multiplayer/public networking
- 官方服务认证
- anti-cheat/protection bypass
- deep client patching
- runtime resource downloads
- GC-Resources dependency
- bundled copyrighted resources
- 与历史 Grasscutter 行为完全对齐
- Windows 之外的 launcher polish

## 战略指导

- 逐步冻结契约：cache 在 v0.3，save 在 v0.4/v0.5，runtime API 在 v0.6，launcher control 在 v0.7。
- Launcher 保持薄层：编排 CLI/runtime API，而不是发明另一套行为。
- 意外删除 save data 是 release-blocking bug。
- 优先可靠 Windows `.zip`/installer + checksum，而不是复杂更新系统。
- 诊断是一等功能。
- v1.0 前不要追求完整 gameplay/protocol parity。
