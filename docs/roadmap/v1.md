# Phanes v1 Roadmap

This roadmap defines the planned path to the first stable Phanes release. It is a planning contract, not a guarantee that every detail will ship unchanged. Contract changes still require explicit review.

## Goal

Ship a Windows-focused, local-first offline runtime, resource-cache builder, and launcher framework that is safe, reproducible, contract-driven, and explicitly not a public server framework.

## Version themes

| Version | Theme |
| --- | --- |
| v0.1 | Contract baseline and embedded-minimal end-to-end |
| v0.2 | Runtime lifecycle, config, and diagnostics |
| v0.3 | Resource cache contract hardening |
| v0.4 | Save-data foundation |
| v0.5 | Local profile/account model |
| v0.6 | Runtime API for launcher |
| v0.7 | Windows launcher prototype |
| v0.8 | Local source detection/import preparation |
| v0.9 | Release candidate hardening |
| v1.0 | Stable Windows-focused local-first release |

## v0.1: Contract baseline and developer preview

### Scope

Establish the first stable internal project shape:

- generated protobuf contracts
- CLI command contracts
- runtime status/shutdown API contract
- resource cache manifest contract
- SQLite schema/migration contract
- embedded-minimal cache path working end-to-end

### Exit criteria

- Fresh checkout can run tests, build CLI, build embedded-minimal cache, verify it, start runtime on `127.0.0.1`, query status, and shut down.
- Runtime never binds to `0.0.0.0`.
- Runtime performs no resource downloads.
- GC-Resources is not required.
- No copyrighted resource payloads are bundled beyond tiny safe fixtures.

### Non-goals

- real launcher UI
- real game integration
- public hosting
- remote resource fetching
- client patching or bypass work

## v0.2: Runtime lifecycle, config, and diagnostics

### Scope

Make runtime behavior predictable and observable as a localhost-only process.

### Deliverables

- versioned config schema
- `phanes config init`
- `phanes config validate`
- `phanes runtime start --config <path>`
- `phanes runtime status --json`
- `phanes runtime logs`
- runtime lockfile/PID handling
- clean shutdown timeout behavior
- `phanes diagnostics collect`

### Exit criteria

- Invalid configs fail with actionable errors.
- Default host is always `127.0.0.1`.
- Explicit `0.0.0.0` is rejected.
- Runtime refuses missing/invalid cache.
- Runtime detects already-running instances.
- Logs and diagnostics are easy to locate on Windows.

## v0.3: Resource cache contract hardening

### Scope

Turn the builder/cache model into a durable, local-only, reproducible contract.

### Deliverables

- versioned resource cache manifest
- cache verifier with clear error categories
- builder output directory layout
- provenance metadata: source kind, tool version, schema version, content hashes
- `phanes cache info`
- `phanes cache clean`
- `phanes cache verify --strict`

### Exit criteria

- Verifier catches missing manifest, schema mismatch, corrupt/missing files, invalid hashes, and unsupported cache versions.
- Embedded-minimal output remains deterministic.
- Runtime consumes cache only through documented contracts.

## v0.4: Save-data foundation

### Scope

Introduce save-data storage as a subsystem separate from resource cache.

### Deliverables

- SQLite save database contract
- migration runner
- `phanes save init`
- `phanes save migrate`
- `phanes save backup`
- `phanes save export`
- `phanes save import`
- clear paths for config, save data, generated cache, and logs

### Exit criteria

- Save DB initializes independently of cache.
- Cache deletion cannot affect saves.
- Backup/export format is documented.
- Migrations are tested from an empty DB.

## v0.5: Local profile/account model

### Scope

Define a safe local identity model for offline use. This is not official authentication.

### Deliverables

- local profile schema/contract
- `phanes profile create`
- `phanes profile list`
- `phanes profile select`
- `phanes profile delete --with-confirmation`
- runtime profile status endpoint
- local-only session model

### Exit criteria

- Runtime can start against a selected local profile.
- Profile data lives in save storage.
- Profile deletion cannot accidentally delete resource cache.
- Documentation clearly states no official authentication bypass and no online service interaction.

## v0.6: Runtime API for launcher

### Scope

Expand runtime API only enough to support launcher process control and diagnostics.

### Deliverables

- finalized status/readiness/shutdown endpoints
- diagnostics API
- redacted config inspection endpoint
- cache/save/profile summary endpoints
- API compatibility policy

### Exit criteria

- Launcher can control runtime using only documented APIs.
- API responses are generated protobuf JSON or validated fixtures.
- Shutdown is idempotent.
- Runtime remains localhost-only.

## v0.7: Windows launcher prototype

### Scope

Introduce a Windows-first launcher shell that controls existing CLI/runtime behavior.

### Deliverables

- Tauri 2 launcher prototype
- runtime start/stop/status controls
- cache status display
- save/profile display
- log viewer
- diagnostics export button
- Windows packaging prototype

### Exit criteria

- Launcher can verify cache, start runtime, show status, stop runtime, and open logs/diagnostics.
- Launcher does not silently mutate system settings.
- Launcher does not patch clients.
- Launcher does not download runtime resources.

## v0.8: Local source detection and import preparation

### Scope

Prepare for user-provided local inputs without bundling copyrighted content.

### Deliverables

- local source detection contract
- `phanes source detect`
- `phanes source inspect`
- `phanes cache build --source local-path --input <path>`
- import provenance in cache manifest
- legal/resource boundary documentation

### Exit criteria

- Builder consumes approved local input shapes.
- Unknown or incomplete input fails safely.
- Runtime depends only on generated cache, not source paths.
- No remote download fallback exists.

## v0.9: Release candidate hardening

### Scope

Freeze v1.0 contracts unless critical issues appear.

### Deliverables

- freeze candidates for runtime API, cache manifest, save schema, config schema, and CLI behavior
- Windows release candidate artifacts
- full docs site: quick start, config, builder/cache, runtime, launcher, diagnostics, boundaries
- migration/upgrade guide
- release checklist
- known issues document

### Exit criteria

- Fresh Windows path tested.
- Existing cache/save upgrade path tested.
- Launcher operates without developer tools.
- Release artifacts are checksummed.
- No undocumented cross-module JSON contracts remain.

## v1.0: First stable local-first release

### Required capabilities

Runtime:

- binds to `127.0.0.1` by default
- has documented status/readiness/shutdown APIs
- uses local config, local save data, and local resource cache
- does not download resources
- provides useful diagnostics

Builder/cache:

- supports embedded-minimal cache generation
- supports approved local input cache generation if ready from v0.8
- produces versioned cache manifests
- verifies cache integrity
- keeps cache separate from save data

Storage:

- SQLite migrations are versioned and tested
- save data supports backup/export/import
- cache deletion cannot destroy save data

CLI:

- stable commands for config, cache, save, profile, runtime, diagnostics, and version

Launcher:

- Windows-focused
- can start/stop runtime
- shows runtime/cache/profile status
- opens logs/diagnostics
- does not patch clients or mutate system network settings silently

Releases:

- GitHub Releases produce Windows artifacts
- checksums are published
- docs are available on GitHub Pages
- upgrade notes are included

### v1.0 release gate

```bash
go test ./...
go vet ./...
phanes version
phanes config init
phanes config validate
phanes cache build --source embedded-minimal
phanes cache verify --strict
phanes save init
phanes profile create local-test
phanes runtime start
phanes runtime status
phanes diagnostics collect
phanes runtime shutdown
```

### v1.0 non-goals

- public server hosting
- multiplayer/public networking
- official service authentication
- anti-cheat/protection bypass
- deep client patching
- runtime resource downloads
- GC-Resources dependency
- bundled copyrighted resources
- full parity with historical Grasscutter behavior
- cross-platform launcher polish beyond Windows

## Strategic guidance

- Freeze contracts progressively: cache by v0.3, save by v0.4/v0.5, runtime API by v0.6, launcher control by v0.7.
- Keep the launcher thin: it should orchestrate CLI/runtime APIs, not invent separate behavior.
- Treat accidental save deletion as a release-blocking bug.
- Prefer reliable Windows `.zip`/installer artifacts with checksums over complex update systems.
- Make diagnostics a first-class feature.
- Do not chase full gameplay/protocol parity before v1.0.
